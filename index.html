Infographic skill map

A set of skills that takes an infographic or storytelling visualisation from brief to validated work: research, analysis, narrative, concept model, rendering, build and validation. The same files run in Claude and in GitHub Copilot. Select a skill in the diagrams or tables to read its instructions.

Loops in general are documented: the sources describe stages that are not strictly sequential. The six specific loops are this design's own inference from that. See the design notes.

What each skill does

SkillDoesReadsWritesChecks
Orchestrator
infographic-process		 Takes the brief at intake: outcome, message, audience, output type, evidence already in hand, constraints, devices and measures. Calls the steps in order, applies the checks, chooses the loop to run, and stops to ask you after two passes of the same loop. A blocked step is repeated and logged separately from the six loops. If the brief itself is wrong, it stops and asks you. The whole record Brief, current step, loop count, decision log
Applies every check below.
Assistant: brief conflict check after steps 1, 2 and 5.
Each check is marked as run by a separate reviewer, or as self-checked.
Step 1
infographic-research		 Domain research and data collection. Corrections to the brief are shown to you before step 3 starts. Brief Source records: what the source is, its date, how reliable it is, the data taken, and whether it corrects the brief
No assistant check of its own. The brief conflict check runs after this step.
Step 2, existing
analytical techniques catalogue		 Applies analytical techniques to the sources and extracts the key insights. The methods stay in the catalogue and are not repeated in this process. Source records Insights, each linked to its sources
Built elsewhere and not yet tested here. The brief conflict check runs after this step.
Step 3
infographic-narrative		 Explores candidate narratives against the outcome and chooses one with you. Brief, insights Candidate narratives, chosen narrative
Assistant: horizontal logic (the titles, read in order, tell the narrative), and no title stronger than the insights behind it.
You: confirm the chosen narrative.
Step 4
infographic-concept-model		 Builds the model that supports the chosen narrative. Each node links to a source record, logic, a finding or a hypothesis, and is marked as evidence, assumption or judgement. Chosen narrative, insights, source records Model nodes
Assistant: every node has a complete source record, and every claim in the narrative has a node.
You: agree any change that weakens or removes a claim.
Step 5
infographic-rendering		 Selects the rendering approach for the output type and tests the options. Chosen narrative, model, output type Rendering decision, with the form of the data for each node
Assistant: coverage test of every node, then a low-fidelity test. The brief conflict check runs after this step.
You: pick the option.
Step 6
infographic-build		 Builds the visualisation. Model, rendering decision The visualisation
Assistant: reverse storyboarding, done blind (the main point of each part, written from the finished work before reading the record, then compared with the narrative).
Assistant: each claim on the page matches what its source says.
Step 7
infographic-validation		 Communication, sharing and workshop validation. Everything in the record Feedback log, and the loop to run if feedback requires one
Assistant: source and traceability checks, and a presentation review.
You: a reader with no context, and the workshop.
A wrong brief is escalated to you. A title change is fixed in place and is not a loop.

Working in Claude and GitHub Copilot

The skills are the same files in both tools. Each is a SKILL.md with only a name and a description in its header, and no bundled files, so the same text works wherever it is installed.

ClaudeGitHub Copilot
Where the file goesThe skill review card in claude.ai, one SKILL.md per skill. Claude Code reads .claude/skills..github/skills, .claude/skills or .agents/skills in a repository, or ~/.copilot/skills for personal use.
How a skill startsClaude matches the task to the skill description.Copilot matches the task to the skill description in the same way.
Optional extras, not needed for the coreClaude Code can stop step skills starting by themselves, so only the orchestrator starts them.A custom agent with handoffs could run the sequence. This is not confirmed in GitHub's documentation.

Because step skills cannot be switched off in the portable format, each step description begins by saying it is one step of the infographic process and is started through infographic-process.

Testing

A running record of each test of the skills and the refinements it led to. Each new test is added below the last.

Test run 1, 4 November 2026

One brief on AI substitution and use, with US and Australian evidence. The output was a scrolling annotated page (output type 2), built in Claude. Intake and steps 1, 3, 4, 5 and 6 ran, and so did the assistant checks in step 7. Step 2 was supplied as a document, because the catalogue skill was not available. One blocked step was repeated, and step 4 was resolved by weakening claims with the person's agreement. Full notes are in test run 1.

Gap foundRefinement
A brief that arrives with evidence already gathered had no rule, and corrections had no route to the person.New intake item for evidence already in the brief. Step 1 verifies it and reports corrections, and the orchestrator shows them to the person before step 3.
The axes of a framing device (a curve) were not defined until step 4.New intake item for devices and measures.
Nothing checked insights or sources against the brief's constraints.New intake item for constraints, and a brief conflict check after steps 1, 2 and 5.
Step 1 did not record whether data could be plotted.New source record field for the data, and a note on the form of the data for each node in step 5.
A long title could not be shortened for a card without changing the narrative.A route for title changes, fixed in place and not counted as a loop. Step 5 no longer rewords titles.
The assistant that made the work also graded it, and the source match came only at step 7.An independence rule (a separate reviewer, or the check is marked self-checked), blind reverse storyboarding, and a source-to-claim match in step 6.
A title could say more than the insights behind it.Step 3 now checks that each title is no stronger than its insights.

The refinements are in commit 47ead15. The horizontal logic check, the completeness check (including its reverse direction) and the reverse storyboarding check each caught a real problem, and the process record kept its state across a context reset. The step 7 checks also found seven errors in the draft page, all fixed before release. They were figures stated more strongly than their sources, and a wrong period for one dataset.
